# Локальный аудит безопасности — Елена Архипова

Актуализация 20.11.2026: по новому требованию заказчика email снова обязателен в HTML, JavaScript и PHP. Упоминания необязательного email ниже описывают состояние на дату исходного аудита. Пустой email теперь отклоняется; контракт и тесты обновлены.

Дата: 17 ноября 2026. Область: рабочий проект HTML/CSS/JS/Vite, форма, сборка, существующая публикация Pages, новая приватная PHP/SMTP-часть. Хостинг и домен REG.RU ещё не куплены. Исходная рабочая копия уже содержала незакоммиченные технические страницы; они сохранены. Push/деплой, изменение workflow GitHub Pages и реальные SMTP-отправки не выполнялись.

## 1. Риски и принятые решения

| Риск / наблюдение | Результат |
|---|---|
| Отсутствовал серверный обработчик; браузерную валидацию можно обойти | Подготовлен PHP/PHPMailer с независимой строгой валидацией. Реальная форма пока выключена конфигурацией; готовность хостинга не заявляется |
| Не было общего серверного антиспам-лимита | SQLite: атомарные счётчики всех окон, IP/IPv6 /64 + глобальные квоты, отдельные квоты SMTP; honeypot; Origin/Fetch Metadata как дополнительные фильтры |
| Текстовые обозначения политики/согласия не были ссылками | Добавлены публичные `VITE_PRIVACY_URL`, `VITE_CONSENT_URL`; при настройке становятся same-origin ссылками. Без обеих ссылок/флага готовности отправка закрыта. Документы не выдуманы, фактическое содержание/доступность ещё должны быть утверждены |
| Лишний обязательный сбор email | Поле сохранено в дизайне, стало необязательным. Обязательные контактные сведения — имя, телефон и согласие; описание дела не добавлено |
| Клиентские проверки не ограничивали все длины при обходе maxlength | Уточнены в JS; PHP самостоятельно проверяет типы, сырую длину, управляющие символы и формат. Неизвестные поля, массивы вместо строк, нестрогий consent, XSS-подобное имя отвергаются |
| Возможность ошибочно опубликовать приватные файлы | `security` вне public; PHPMailer/config/SQLite не в dist. Сборка автоматически проверяет allowlist путей/расширений, source maps, symlink и некоторые шаблоны секретов. Добавлены ignore-правила |
| Непроверенные редиректы API | `fetch` теперь с `redirect:'error'`; сохранены same-origin, HTTPS вне loopback, таймаут и запрет автоматического повтора |
| Почтовая инъекция / ложный успех | Фиксированные заголовки From/To/Subject, авторизованный From, plaintext, исключения наружу не попадают. Только принятие PHPMailer/SMTP даёт `{ok:true}`, конечная доставка не гарантируется |
| Веб-сервер/HTTPS/заголовки ещё неизвестны | Подготовлен только условный Apache-шаблон; CSP проверена локально в браузере. Redirect/HSTS отключены до хостинга. nginx не получает неподходящий .htaccess |
| Известная уязвимость dev-зависимости picomatch | **Осталась upstream:** npm audit — 4 high-записи по цепочке picomatch → fdir/tinyglobby/Vite. Исправленной версии пока нет, см. ниже. Не названо исправленным |

Во время разработки тест сырых длин выявил возможность принять телефон с лишними начальными пробелами после trim; серверная проверка перенесена также на исходные длины. Браузерная проверка CSP выявила CRLF в inline bootstrap: генератор хешей теперь учитывает HTML-нормализацию CRLF/CR → LF, поэтому прелоудер не блокируется.

## 2. Проверка существующих механизмов

- `form.js`: сохранены текстовые ошибки через `textContent`, строгая проверка HTTP + `{ok:true}`, таймаут 15 секунд, блокировка параллельной отправки, сброс только после подтверждения, событие `elena:form-success` и переход на thanks с учётом base. Ненастроенная форма не выполняет POST.
- HTML/JS: `innerHTML` в прелоудере/мобильной адаптации получает статические строки проекта или собственную исходную разметку, а не значения формы, query string или ответа сервера. Слайдер использует `textContent`/DOM API. В проверенных путях не обнаружен поток недоверенного ввода в HTML-синк; это не доказательство отсутствия всех возможных XSS.
- `vite.config.js`: существующее экранирование SEO и данных практик сохранено. Метаданные/JSON-LD/статические услуги не удалены. Сборка без source maps. Приватный каталог закрыт и от dev-сервера; Vite слушает loopback. Dev/preview не являются production-серверами.
- Скрипты и шрифты локальные. Автоматически подключённых внешних скриптов, счётчика, CDN-библиотек нет. Аналитический модуль сохраняет проверку согласия и передаёт только фиксированные goal names, без полей формы. Статические SVG/social placeholders не стали каналом передачи заявок.
- `.env`: в рабочем дереве найден только `.env.example`, без реальных значений; клиентские переменные публичны, SMTP в них не добавлялся. `.gitignore` защищает локальные конфигурации, `.env`, зависимости, SQLite, логи/ключи/backup и тестовые артефакты.
- Workflow Pages прочитан, не изменён. В нём по-прежнему только статическая сборка; добавление PHP в исходники не включает его в артефакт. В будущем можно отдельно согласовать pinning Actions по commit SHA и `npm ci`; в рамках запрета менять публикацию workflow не трогался.
- Pattern scan рабочего дерева и Git-history не нашёл AWS/GitHub/private-key шаблонов. Это выборочная проверка форматов, не полное распознавание любого секрета; реальные SMTP-учётные данные не создавались и не запрашивались.

## 3. Серверная архитектура

Публичный `security/php/contact.php` вручную размещается как endpoint после покупки хостинга. `App.php`, `config.php`, `vendor`, SQLite остаются вне document root; публичный вход проверяет реальные пути и отказывается работать при публичном приватном каталоге/хранилище.

PHP 8.4+, PHPMailer **7.2.0**, фиксированный `security/composer.lock`. SMTP только SMTPS:465 или STARTTLS:587 с `verify_peer=true`, `verify_peer_name=true`, `allow_self_signed=false`. Debug и X-Mailer отключены. Пользовательские значения идут только в plain-text тело, не в заголовки. SMTP-логин/пароль/получатель задаются на сервере отдельно; выключенный шаблон не является рабочей конфигурацией.

Только POST JSON UTF-8, максимум 4096 байт с проверкой фактически прочитанного потока; без неожиданных полей/контент-кодирования. HTTP: 405/415/413/403/400/422/429/502/503; безопасный JSON, no-store, nosniff, запрет встраивания и CORS. Успех только после транспортного подтверждения; при SMTP-исключении — 503 без раскрытия деталей.

Квоты: 5 попыток/IP/мин, 20/час, общий предел 100/10 мин; 3 SMTP-попытки/IP/час, 50 общих/сутки. Фиксированные окна; это ограничивает ущерб, но не устраняет распределённый DoS. Параллельность — SQLite `BEGIN IMMEDIATE`; при ошибке хранилища нет обхода. `REMOTE_ADDR`, без доверия клиентскому X-Forwarded-For. База содержит HMAC-псевдонимы IP/подсетей, окна и счётчики, не заявки. Окончившиеся окна очищаются следующим запросом; режим хранения/доступа и инфраструктурные логи согласовать отдельно.

## 5. Остаточная npm-зависимость

[GHSA-fc5q-39xc-vjpf / CVE-2026-112366](https://github.com/advisories/GHSA-fc5q-39xc-vjpf): ReDoS при обработке специально сформированных extglob-шаблонов, picomatch <=4.0.7; на дату проверки advisory не указывает исправленную версию. Четыре high-записи — транзитивная цепочка одного advisory, не четыре найденные уязвимости формы.

Это dev/build-зависимость: статическая production-сборка её не содержит, сайт не принимает пользовательские glob patterns. Vite закрыт loopback; не размещать dev server в интернете и не собирать недоверенные проекты/шаблоны. Полное устранение upstream-проблемы **не выполнено**: опасный `npm audit fix --force` с предложенным откатом до Vite 6.2.7 не применялся. Перед выпуском повторить npm audit, проверить исправление upstream и совместимость обновления. `npm audit --omit=dev` не заменяет полный аудит и не использовался для сокрытия результата.

## 6. Изменения файлов в рамках безопасности

- Новая папка `security/`: три документа; приватное PHP-приложение/публичный вход; выключенный SMTP-пример; Composer manifest/lock; Apache-шаблон/генератор; проверки public/секретов и локальные PHP/HTTP/конкурентные/браузерные тесты.
- `src/js/form.js`: длины/форматы, необязательный email, honeypot, gate двух документов, запрет redirect API, точный текст SMTP-подтверждения. Предыдущий переход на thanks сохранён.
- `index.html`: скрытый honeypot, необязательный email, метки для ссылок документов; существующая вёрстка сохранена.
- `src/styles/components.css`: скрытие honeypot без участия в layout и регистр текста юридических ссылок.
- `.env.example`: только публичные URL документов, без реальных значений. `.gitignore`: приватные конфигурации/зависимости/инструменты/артефакты.
- `vite.config.js`: постпроверка любого build outDir, явный запрет source maps, loopback/dev fs deny приватного каталога. `package.json`, `package-lock.json`, workflow публикации не изменены.
- `README.md`: актуальный контракт формы и ссылки на приватную документацию. Существующая QA-проверка email обновлена для его необязательности; комментарий интеграционного теста дополнен URL тестовых документов.

## 7. Ещё требуется на реальном хостинге

Все действия подробно в [DEPLOY-REG-RU.md](DEPLOY-REG-RU.md): выбор тарифа/веб-сервера/PHP/extensions, приватные пути/open_basedir/права и блокировки SQLite; действующий endpoint и точный Origin; SMTP/TLS/получатель; HTTPS/продление/редирект; Apache или эквивалент nginx; CSP-хеши финальной сборки; HTTP-проверка закрытых файлов; реальный IP за прокси; WAF/APM/access logs; SPF/DKIM/DMARC; ограниченный тест приёма/доставки с разрешения получателя; backup и восстановление.

С заказчиком согласовать юридические документы, оператора, основание/локализацию/обработчиков, сроки хранения почты, HMAC-квот и инфраструктурных логов, доступы и аналитику. Полное юридическое соответствие не утверждается. Локальная готовность обработчика не означает настроенную защиту REG.RU или подтверждённую доставку писем.
