# Итоговый сайт — arxipova.ru

Сборка: `powershell -ExecutionPolicy Bypass -File security/scripts/package-reg-ru.ps1` из корня приложения. Архивы в `security/.generated/final-site/` исключены из Git. Паролей в сборке нет. GitHub Pages workflow не меняется; эта сборка предназначена для REG.RU.

1. Сохраните резервную копию проверенной приватной SMTP-конфигурации в защищённом месте. В менеджере хостинга переименуйте `/private/mail-test-config.php` в `/private/smtp.local.php`. Не загружайте пароль в Git. Права файла 600, папки private 700. Поле access_key оставьте: оно используется для ключа HMAC лимитов.
2. Загрузите private-final.zip в существующую private и распакуйте прямо туда. config.php, App.php, vendor и runtime должны оказаться непосредственно в private. Архив НЕ содержит smtp.local.php и не заменяет пароль. runtime: права 700; config.php: 600. Убедитесь, что пустая runtime создана после распаковки.
3. Загрузите public-final.zip в `/www/arxipova.ru/` и распакуйте прямо туда. index.html, .htaccess, assets и api должны быть непосредственно в корне сайта. Не загружайте исходники, папку security или private в www.
4. Удалите оба ZIP с сервера и публичный mail-test.php. Удалите приватный mail-test.lock, когда тестовая страница уже удалена. smtp.local.php оставьте: теперь это рабочие настройки.
5. Откройте https://arxipova.ru. Проверьте главную, меню, услуги, ссылки, политику, согласие, 404 и мобильную версию. Если .htaccess вызывает 500, временно переименуйте его и проверьте разрешённые директивы Apache у REG.RU; не удаляйте приватную защиту.
6. Проверьте модули PHP 8.4: openssl, mbstring, pdo_sqlite. Основной обработчик использует SQLite для лимитов, тест SMTP этого не проверяет. При отсутствии расширения включите его в панели или обратитесь в поддержку.
7. С вымышленными данными отправьте одну заявку, отметив согласие. Страница Спасибо должна открыться только после SMTP-подтверждения. Проверьте полное письмо во Входящих/Спаме. SMTP-приём не гарантирует окончательную доставку.
8. GET https://arxipova.ru/api/contact.php должен возвращать 405 и безопасный JSON. https://arxipova.ru/private/config.php и /.env не должны раскрывать файлы. Проверьте заголовки и отсутствие загрузки PHP как текста.

До приёма реальных заявок согласуйте юридические документы с оператором, указанные сроки хранения и порядок удаления писем. Флаги готовности включены в комплекте для запуска существующих страниц; это не заключение о юридическом соответствии. В config.php можно выключить enabled до завершения проверки. Публичный контактный Mail.ru оставлен прежним; получатель формы — info@arxipova.ru.

Используйте только https://arxipova.ru (без www). HTTPS/канонический редирект настройте в панели после проверки сертификата; шаблон .htaccess не включает HSTS и редирект заранее. Проверьте DNS/SPF/DKIM/DMARC и настройки резервного копирования по DEPLOY-REG-RU.md. Пароли в приватных резервных копиях защищайте; не архивируйте базу лимитов без необходимости.
