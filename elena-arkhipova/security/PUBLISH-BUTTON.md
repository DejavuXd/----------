# Публикация по кнопке

Workflow `.github/workflows/reg-ru.yml` запускается только вручную из main. Существующая публикация GitHub Pages не изменена. Это обновление статического сайта: api/contact.php, private, пароль почты, база лимитов и почтовые ящики не загружаются и не удаляются. Для изменений PHP используйте отдельное ручное развёртывание.

## Однократная настройка

1. Уточните у REG.RU поддержку явного FTPS на порту 21 и имя сервера с действующим TLS-сертификатом. Обычный FTP не подходит. Если поддерживается только SFTP/SSH, этот workflow не запускайте: требуется другой транспорт. Проверка сертификата не отключается.
2. Создайте отдельного FTP-пользователя, ограниченного папкой www/arxipova.ru. Его FTP-корень `/` должен показывать index.html, assets, api и .htaccess. Не используйте основной доступ ко всему аккаунту хостинга. Публикация требует разрешения записи и переименования файлов.
3. В GitHub: Settings → Environments → New environment → `reg-ru-production`. Ограничьте deployment branches веткой main. Добавьте environment secrets: `REG_RU_HOST` (имя сервера без протокола/пути), `REG_RU_USER`, `REG_RU_PASSWORD`. Это данные отдельного FTPS-пользователя, НЕ почты. В чат их не отправляйте.
4. Сохраните свежий бэкап сайта перед первой публикацией. Не запускайте одновременно с ручной загрузкой.

## Каждое обновление

Сохраните проверенные правки в main. Actions → «Опубликовать на REG.RU» → Run workflow → ветка main → подтверждение `arxipova.ru` → Run workflow. GitHub показывает статус выполнения; дождитесь зелёной отметки и проверьте новую версию сайта, меню и форму.

Скрипт загружает ресурсы, затем .htaccess с хешами новой сборки, затем страницы (главную последней). Каждый файл сначала загружается во временное имя и переименовывается; это не атомарная замена всего сайта. Во время публикации возможна краткая несовместимость CSP и старых страниц. При ошибке часть файлов может уже обновиться: повторите после устранения причины либо восстановите бэкап. HTTPS-проверка подтверждает доступность, но не отправляет реальную заявку.

Старые ресурсы не удаляются автоматически, чтобы не ломать открытые вкладки. Периодическая очистка возможна отдельно после бэкапа. Временные файлы не содержат SMTP-секретов. Секреты доступны runner GitHub во время запуска — это передача доступа к публичной папке сайта сервису GitHub Actions; пароль должен быть отдельным и ограниченным.
