# Страницы 404 и благодарности

## Дизайн и адаптация

Первичные данные получены через **Figma Bridge 0.0.27**, подключённый к открытому документу «Адвокат Лендинг (Copy)» (Bridge обозначает его как `unsaved-mwkqhwxc-et7f0vrw`). Использованы указанные пользователем узлы новой копии `1VCFBSh2MzMoH5CgTmZHa4`:

| Страница | Узел | Размер |
| --- | --- | --- |
| Ошибка 404 | 2401:409 | 1200 × 588 px |
| Благодарность | 2401:720 | 1200 × 588 px |

Прочитаны полные деревья `get_node`: размеры/позиции, Auto Layout, padding/gap, выравнивание, типографика и текст, цвета, границы, компоненты шапки и CTA. PNG обоих эталонов получены через `save_screenshots`. Для крупного 404 дополнительно получены absoluteRenderBounds: они отличаются от логических размеров текстового слоя; это учтено при размещении оригинального векторного экспорта.

Оригинальные SVG логотипа, крупного декоративного номера 404 и социальных значков находятся в `public/technical/`. Номер 404 также доступен как текст в H1 для скринридеров. Экспорт стрелки из двух вложенных instance-узлов завершился ошибкой Bridge «Unable to establish connection to Figma after 10 seconds»; переиспользована существующая стрелка сайта из того же компонентного оформления. Новая иконка не рисовалась. Временных ссылок на ассеты Figma в коде нет.

Скриншоты сверены на исходной ширине 1200 px; после сравнения исправлены масштаб/позиция номера 404, межабзацный интервал, ширина телефонной кнопки, пробелы при снятии десктопных переносов и растягивание мобильной кнопки возврата. На коротких экранах доступна обычная вертикальная прокрутка, содержимое не обрезается. До 800 px страницы перестраиваются в одну колонку. Отдельные телефонные/планшетные фреймы не предоставлены — промежуточная композиция адаптирована по двум десктопным эталонам.

Ограничение существующих шрифтов сохраняется: кириллический PP Neue Montreal Regular в проекте отсутствует, поэтому для обычного текста используется уже подключённый Inter Tight. Некоторые глифы/переносы отличаются от Figma; полного pixel-perfect совпадения типографики не заявляется. Декоративный номер и логотип экспортированы из исходных слоёв, а не заменены другими шрифтами.

## Реализация

- `404.html`, `thanks.html` — две отдельные семантические HTML-страницы с одним H1 и `noindex, follow`.
- Общие шапка, подвал и стартовый скрипт прелоудера берутся напрямую из `index.html` через `src/technical-pages-plugin.js`; отдельная копия шапки удалена. Ссылки на секции возвращают на главную с учётом base. Контакты мобильного меню берутся из общего подвала.
- `src/js/technical.js`, `src/styles/technical.css` — стили и инициализация технических страниц, включая существующий `setupPreloader()`. Подключена общая таблица `preloader.css`, сохранены reduced motion и аварийное снятие оверлея. Существующие стили главной не изменены.
- `src/js/navigation.js` — добавлен необязательный источник контактов и обработка отсутствующего footer; сохранены анимация, fixed-кнопка, Escape, фокус и scroll lock.
- `src/js/form.js` — после HTTP 2xx **и** JSON `{ "ok": true }` сохранены сброс формы, событие `elena:form-success` и статус успеха, затем добавлен переход на `${BASE_URL}thanks.html`. При ошибках переход не выполняется.
- `vite.config.js`, `src/technical-pages-plugin.js` — MPA-сборка трёх HTML-входов, подстановка общих блоков, ограничение SEO-плагина главной страницей, настоящая HTTP 404 в dev/preview для неизвестных HTML-адресов.

GitHub Pages автоматически использует `dist/404.html` для неизвестного пути. На другом хостинге понадобится настроить его обработчиком HTTP 404. Это не универсальная страница для сетевой недоступности или ошибки сервера 500. GitHub Actions не изменялись.

## Проверки

`qa/technical-pages-check.mjs` выполнен для локальной root-версии и сборки с GitHub Pages base `/----------/`:

- По 14 ширин для обеих страниц: 320, 360, 375, 390, 414, 428, 495, 600, 768, 820, 1024, 1200, 1440, 1920 px. Горизонтального переполнения нет, изображения и шрифты загружаются.
- Меню открывается, закрывается Escape и возвращает фокус кнопке; кнопка возврата ведёт на главную с правильным base.
- Неизвестный вложенный путь возвращает **HTTP 404** с новым оформлением. В сборке для Pages ссылки и ресурсы ведут в `/----------/`, даже когда сам неизвестный URL вложенный.
- Пять сценариев формы: `{ok:false}`, HTTP 500, сетевая ошибка, HTML вместо JSON, успешное подтверждение. Только последний переходит на `thanks.html`; событие успеха срабатывает до перехода. Все POST перехватывались браузером, реальные заявки не отправлялись.
- В обычной ненастроенной конфигурации валидная форма остаётся на главной с ошибкой отправки и не выполняет POST.
- Дополнительно проверены короткие экраны 320 × 568 и 768 × 500, исходные 1200 × 588 и широкие 1920 × 883: кнопки имеют штатную высоту, обрезания и горизонтального переполнения нет.
- Существующая проверка `qa/menu-animation-check.mjs` главной повторена после изменения общего модуля навигации.
- `npm run build` и `node qa/seo-check.mjs` проходят. Сборка с `--base=/----------/` и SEO-проверка с этим base также проходят. Предупреждение о пустом `SITE_URL` прежнее, SEO-настройки не менялись.

После добавления общих блоков повторно проверены обе страницы на 320, 390, 495, 768, 1024, 1200, 1440 и 1920 px: подвал не перекрывает содержимое, горизонтального переполнения и дубликатов ID нет. На 1200 px координаты и размеры логотипа, навигации и телефонной кнопки совпадают с главной; на светлом фоне изменён только контраст ссылок и телефона. Прелоудер действительно анимируется, снимает inert и удаляется; меню, открытое у подвала, корректно блокирует его и возвращает доступ после Escape. Проверен также режим reduced motion. Сборка в ограниченной среде выполнена через `npm run build -- --configLoader runner` (штатный загрузчик esbuild упирается в запрет чтения родительских директорий).

Выгрузки Figma и локальные PNG/JSON результатов лежат в игнорируемых папках `qa/figma-bridge/technical/`, `qa/mobile-check/technical/` и `qa/mobile-check/technical-shared/`.

Реальная доставка заявки требует действующего same-origin обработчика (`VITE_CONTACT_ENDPOINT`) и ранее предусмотренного подтверждения юридических документов (`VITE_CONTACT_LEGAL_READY`). Эти production-настройки не изменялись. Для проверки успешной отправки использовались отдельные локальные Vite-процессы с тестовыми переменными окружения и подставленными ответами; `.env` не создавался и не редактировался.

Коммит, push и публикация в рамках этой задачи не выполнялись.
