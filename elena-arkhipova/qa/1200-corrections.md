# Правки макета 1200 px — 08.11.2026

## Основания и пределы сверки

Задание: `codex_elena_arkhipova_1200px_pravki.txt`.
Проведена визуальная сверка всех секций с предоставленным PDF «Главная 1200px Золотистый вариант» и проверка размеров его текстовых объектов через pdfplumber. Нового доступа к свойствам Figma нет; полное попиксельное совпадение с Figma не заявляется.

PDF подтверждает: основной заголовок 40 px; описания hero, карточек, практики, биографии и консультации 11 px; кнопки 12 px; список услуг 14 px; нижняя строка футера 10 px. Межстрочный интервал описания hero/карточек — 15 px, практики/биографии/консультации — 14 px, списка услуг — 17 px. Шрифты из материалов сохранены. Неизвестные параметры других заголовков не заменены интервалом из h1.

В браузере Windows при viewport 1200 px доступная ширина документа 1185 px из-за полосы прокрутки. Размеры rem при этом соответствуют 1 px. Полное совпадение координат с холстом Figma шириной 1200 px поэтому не предполагается. Принудительные переносы для подгонки не добавлялись; h1 теперь переносится естественно. Существующие редакционные переносы в остальных блоках сохранены с обычными пробелами, чтобы при скрытии br на мобильных слова не склеивались.

## Изменённые компоненты

- `index.html`: единые SVG-стрелки с currentColor, видимые подписи полей, естественный перенос h1, разделение слов около адаптивных br, скрытая точка подключения соцсетей.
- `src/styles/layout.css`, `components.css`, `responsive.css`: типографика и переносы, геометрия стрелок, индивидуальный hover телефона и слайдера, floating labels, фокус без дополнительного outline/box-shadow, футер 32/58/16/58 и нижняя строка 10 px. Мобильные размеры текста и зоны нажатия сохранены.
- `src/styles/motion.css`: убрана рамка карточек; четыре отдельных сценария декоративных символов с плавным возвратом. Без pointer-курсора. Сохранён reduced motion.
- `src/js/motion.js`: offscreen-анимации готовятся в paused-состоянии до наблюдения, запускаются перед входом в экран и только один раз. Это устраняет переход уже видимой карточки обратно в opacity:0. Защита от повторной инициализации, отмена при смене настройки движения/фокусе. Раскрытие большой фотографии — две временные transform-маски вместо анимации clip-path всей фотографии и масштабирования изображения; маски удаляются после завершения/отмены. Новых scroll-обработчиков нет.
- `src/js/form.js`: явные состояния статуса, очистка устаревшего сообщения при редактировании. Валидация и условие подтверждения успешной отправки сохранены.
- `qa/motion.test.mjs`: регрессия ранней подготовки, однократного запуска, повторной инициализации и отмены ожидающих анимаций.

Логика, порядок, цикличность, тексты и временные параметры переходов слайдера не изменены. Общие функции анимации получили необязательные параметры для секций, их прежние значения по умолчанию сохранены для слайдера.

## Проверено

- Production-сборка `npm.cmd run build`.
- `node --test qa/motion.test.mjs`: 4 теста.
- Браузер: 1920, 1440, 1200, 1024, 768, 480, 375, 320 px — без горизонтального переполнения.
- На 1200: h1 40/40 px, tracking -0.8 px; все стрелки 2.5×5 px; обычные контейнеры 12×12 px, gap телефона 2 px; кнопки слайдера 24×24 px без дополнительных контейнеров; футер с заданными отступами/шрифтом.
- Hover телефона: #140D09 / #F5F2E9, включая SVG. Его размеры до/после одинаковы (117.640625×37.5 px).
- Hover слайдера: #EEA824 / #2D2D2D, прозрачная граница, размер не меняется. Переключение на гражданскую практику работает.
- Каждый из четырёх hover-сценариев проверен в браузере. Обводки/псевдообводки карточек отсутствуют, курсор обычный. После прокрутки карточки остаются видимыми; временные маски фотографии удалены.
- Форма: пустая отправка, сообщения ошибок, фокус первого неверного поля, исправление ошибок при вводе, Tab, сохранение поднятой подписи заполненного поля, отсутствие внешней обводки. Проверены desktop и mobile.
- Подтверждение отправки реальных заявок не проверялось: адрес приёма заявок и юридическая готовность по-прежнему не настроены. Успех не имитируется. Состояние успеха по-прежнему появляется только после HTTP-успеха и ответа `{ok:true}`.

Замер FPS/профиль рендеринга и системное переключение reduced motion в браузере не выполнялись. Отмена движения проверена автоматическими тестами. Приложение не использует бесконечных анимаций или вычислений на каждом scroll.
