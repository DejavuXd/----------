# Елена Архипова

Самостоятельный сайт: HTML5, CSS3, Vanilla JavaScript ES Modules, Vite. Фотографии извлечены из предоставленного PDF, без генерации или замены лиц.

## Запуск

```sh
npm install
npm run dev
npm run build
npm run preview
```

Готовые статические файлы сборки находятся в `dist/`. Версия адаптирована до 1920 px; подключены локальные шрифты Inter Tight и Neue Montreal, SVG-логотип и четыре направления практики. Актуальная проверка описана в `qa/1920-status.md`. Для формы подготовлен отдельный PHP/SMTP-обработчик в `security/`; реальные домен, хостинг и почтовая доставка ещё не настроены.

## Что требует завершения

- Сверить точное назначение двух предоставленных шрифтов и размеры со свойствами Figma, когда будет доступна инспекция. Оба семейства уже подключены.
- При наличии заменить фотографии практик 221 × 294 версиями высокого разрешения. Все четыре направления уже реализованы; автопрокрутки нет.
- Утверждённые политика конфиденциальности и согласие: разместить документы, заменить текстовые обозначения ссылками, затем установить `VITE_CONTACT_LEGAL_READY=true`.
- Подтверждение контактов, профессиональных сведений и текста, перенесённых из PDF; ссылки социальных кнопок. Социальные кнопки без адресов не добавлены; исходный SVG-логотип подключён.
- Домен для canonical, материалы Open Graph.

## Контракт формы

После подтверждённого ответа HTTP 2xx с JSON `{ "ok": true }` форма отправляет событие `elena:form-success` и переводит на `thanks.html`. Путь учитывает Vite `base`, в том числе `/----------/` на GitHub Pages. При ошибке или отсутствии конфигурации форма остаётся на текущей странице. Реальный серверный обработчик по-прежнему требует настройки.

Скопировать `.env.example` в `.env`, указать `VITE_CONTACT_ENDPOINT=/api/contact.php` только для будущего PHP-хостинга после настройки обработчика на том же origin. Указать `VITE_PRIVACY_URL` и `VITE_CONSENT_URL` на утверждённые документы; без обеих ссылок форма остаётся закрытой. `VITE_` переменные публичны: в них нельзя хранить ключи или пароли. На GitHub Pages PHP не работает; текущая публикация не изменена.

Запрос: POST JSON `{ name, phone, email, consent: true, website: "" }`; имя, телефон и email обязательны, website — скрытый honeypot. Успех: HTTP 2xx и JSON `{ "ok": true }`, возвращённые после подтверждённого приёма письма SMTP-сервером. Это не гарантия конечной доставки. Клиент не считает обычную HTML-страницу или произвольный HTTP 200 успешной отправкой. Предусмотрен таймаут 15 секунд; при неопределённом результате нет автоматического повтора, чтобы не дублировать заявку. HTTP-редиректы API запрещены.

Приватный PHP/PHPMailer-обработчик, тесты и инструкции находятся в `security/`; начинать с [архитектуры](security/README.md) и [развёртывания REG.RU](security/DEPLOY-REG-RU.md). Он повторно проверяет данные и ограничивает частоту запросов атомарными квотами SQLite. Хостинг и SMTP ещё не настроены. Без endpoint и утверждённых юридических документов форма не отправляет данные и предлагает связаться по телефону. Данные не сохраняются в localStorage и не пишутся в консоль. После каждой сборки автоматически проверяется публичное содержимое `dist`; PHP, конфигурации и документация безопасности туда не копируются.

## Проверка

### Юридические страницы и cookie

`privacy.html` и `consent.html` сверстаны по Figma 2434:202/2434:397, cookie-баннер — 2435:662 (копия 6lLSGKOwDzL3qvnyvtNFWY). Общие шапка, подвал и прелоудер сохранены; ссылки в подвале и форме учитывают Vite base. URL документов по умолчанию ведут на эти страницы; переменные VITE_PRIVACY_URL/VITE_CONSENT_URL остаются необязательными переопределениями. Наличие страниц не включает SMTP и не меняет VITE_CONTACT_LEGAL_READY.

Cookie-выбор хранится в localStorage под `elena-cookie-preferences-v1` до 180 дней, без контактных данных. До выбора и при «Только необходимые» аналитика запрещена. «Настроить» позволяет отдельно выбирать функциональные/аналитические категории; «Настройки cookie» в подвале позволяет пересмотреть выбор. Изменения синхронизируются между вкладками. Внешний счётчик автоматически не подключается. При недоступном localStorage выбор действует до перезагрузки. Тексты документов перенесены из макетов; фактические домен, хостинг, обработчики и сроки хранения требуют подтверждения перед публикацией.

Проверены 12 сочетаний двух страниц и ширин 320/390/768/1024/1200/1920, ссылки, сохранение выбора, повторное открытие настроек и переключение «все → необходимые». Сборки для корня и GitHub Pages base проверяются отдельно. Отдельных мобильных фреймов по данным ссылкам нет: узкие экраны адаптированы из desktop-композиции.

### Технические страницы

- `404.html` — страница неизвестного адреса. Сборка кладёт её в корень `dist`, где GitHub Pages использует её как custom 404. Для другого хостинга нужно назначить этот файл обработчиком HTTP 404. Это не обработчик сетевых ошибок или HTTP 500.
- `thanks.html` — страница благодарности. Обе технические страницы закрыты от индексации через `noindex, follow` и не добавляются в sitemap.
- Dev/preview Vite также возвращают оформленную 404 с настоящим HTTP-статусом для неизвестных HTML-адресов.
- Шапка, подвал и стартовая разметка прелоудера технических страниц берутся из `index.html` плагином `src/technical-pages-plugin.js`. Ссылки на секции ведут на главную с учётом base. Используются существующие анимированное меню и прелоудер; стили страниц — в `src/styles/technical.css`. Десктопная шапка сохраняет геометрию главной, с тёмными ссылками и телефонной кнопкой на светлом фоне.

`qa/technical-pages-check.mjs` проверяет адаптивы, меню, неизвестный вложенный адрес и переход формы при подставленных браузером тестовых ответах. Реальные заявки при проверке не отправляются. Подробности запуска указаны в начале файла.

`qa/browser-check.mjs` использует установленный отдельно Playwright и Edge, не добавляя их в зависимости сайта. Перед проверкой запустить Vite на порту 5173:

```sh
node qa/browser-check.mjs /absolute/path/to/playwright/index.mjs
```

Проверяются восемь контрольных ширин, отсутствие горизонтального переполнения, загрузка изображений, мобильная навигация, ошибки формы, отсутствие отправки без настроек, reduced motion и ошибки консоли. Скриншоты сохраняются в `qa/screenshots`. Проверка реальной доставки требует настроенного серверного обработчика. Визуальную точность типографики можно оценить только после подключения согласованного шрифта.
