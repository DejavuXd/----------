# Технический SEO-аудит и внедрение

Дата: 16 ноября 2026. Работа выполнена локально, без коммита и деплоя.

## Исходное состояние

Сайт на HTML/CSS/JavaScript и Vite 7.3.7; сторонних библиотек анимаций нет. Конфигурации Vite не было. Title и description существовали, но не выделяли основной регион. HTML содержит один H1, разделы, контакты, биографию и первое направление практики. Три других направления существовали только в JavaScript. Open Graph, canonical, sitemap, robots и JSON-LD отсутствовали. Документ SEO_техническое_задание_верстальщику_Елена_Архипова.docx в рабочей папке не найден.

Утверждённый H1 «Судьба дела зависит от правильного шага» сохранён. Названия секций и основные тексты не заменялись рекомендованными SEO-вариантами. Дизайн и анимации сохраняются. Упоминания Смоленска уже есть в логотипе, первом экране и контактах. Подписи фактов первого экрана остаются H2, поскольку они представляют смысловые блоки, а не декоративные номера.

## Что уже было правильно

- lang=ru, UTF-8, viewport, один H1 и семантические разделы.
- Телефон tel: и email mailto:, реальные сведения о квалификации и реестровом номере.
- Главный портрет с fetchpriority=high, без lazy; изображения ниже первого экрана с lazy и размерами.
- WebP: главный портрет 95 914 байт (1920×1080), Фемида 164 612 байт, четыре картинки практик 10 964–14 096 байт. Новые варианты srcset не создавались: существующие файлы уже небольшие; значимый выигрыш без перекодирования не установлен. Фото «Обо мне» PNG — 204 500 байт, сохранено качество утверждённого материала.
- Шрифты WOFF2, font-display: swap, preload основного шрифта; SVG favicon уже есть.
- Прелоудер декоративный, имеет страховочный таймер, не зависит от window.load. Reduced motion поддерживается.
- Форма проверяет имя, телефон, почту и согласие, блокирует повторную отправку, использует таймаут. Успех требует подтверждения сервера. Персональные данные не логируются.
- .gitignore исключает .env, node_modules и dist.

1. npm run build — успешно. Предупреждение об отсутствующем SITE_URL ожидаемо.
2. node qa/seo-check.mjs — успешно: один H1, один title/description, четыре направления в HTML, JSON-LD разбирается, ID уникальны, локальные src/href и CSS url() существуют, случайного noindex нет.
3. Изолированная сборка с --base=/repository/ и тестовым SITE_URL — успешно; проверены canonical, og:url/image, sitemap/robots и ресурсы в подпапке. Результат только в игнорируемой node_modules/.cache/seo-fixture. В основном dist тестового домена нет.
4. Проверки validateContact для пустого и корректного тестового ввода — успешно; запросы не отправлялись.
5. Итоговая основная сборка: HTML ~25,05 КБ, CSS ~23,37 КБ (gzip 5,57), JS ~17,07 КБ (gzip 6,73), без новых зависимостей.

Браузерные проверки консоли, интерактивности и геометрии на 320, 360, 375, 390, 428, 768, 1024, 1200, 1440 и 1920 px не выполнялись. Изучены существующие медиазапросы, но это не заменяет визуальное тестирование. Lighthouse/PageSpeed и полевые LCP/INP/CLS не измерены; соответствие целевым показателям не заявляется. Длительность заставки и загрузка шрифтов остаются кандидатами для диагностики после публикации.

## Настройка после выбора домена

В локальном .env задайте SITE_URL — окончательный HTTPS-адрес с завершающим слешем — и выполните npm run build. URL проверяется; query, hash, учётные данные и HTTP не допускаются. Без SITE_URL canonical, og:url/image и sitemap отсутствуют намеренно. Не используйте тестовый домен в production.

На коммерческом домене в корне: npm run build (base остаётся стандартным /). Загружать содержимое dist, включая robots.txt и будущий sitemap.xml. Для GitHub Pages в подпапке: npm run build -- --base=/ИМЯ-РЕПОЗИТОРИЯ/. SITE_URL должен соответствовать реальному размещению, если оно каноническое; адрес Pages автоматически каноническим не назначается. Robots.txt в подпапке GitHub Pages не управляет корнем всего github.io — root robots настраивает владелец хоста.

OG использует реальный портрет 1920×1080 и его существующий файл; это не отдельная карточка 1200×630. После указания домена проверьте результат в мессенджерах. Apple Touch Icon не добавлен: подходящего утверждённого PNG нет, SVG favicon сохранён.

На хостинге настроить HTTPS, единственный хост с серверными 301, настоящие 404; HTML/robots/sitemap отдавать с повторной проверкой кеша, хешированные assets — с длительным immutable-кешем. Нехешированные images/fonts не помечать immutable без версионирования. Конфигурация конкретного веб-сервера не изменялась.

## Что требует участия владельца

1. Указать окончательный домен и хостинг; после загрузки проверить HTTPS/редиректы и публичные robots/sitemap.
2. Подтвердить статус практики/адрес для LegalService. Сейчас используются только Person и WebSite на основании видимых данных.
3. Предоставить обработчик формы и утверждённые документы политики/согласия. Подключить реальные ссылки вместо текстовых заглушек; затем VITE_CONTACT_ENDPOINT и VITE_CONTACT_LEGAL_READY=true. Пока отправка заблокирована.
4. Обработчик должен принимать POST JSON {name, phone, email, consent}, отвечать JSON {ok:true} только после принятия заявки. Нужны серверная валидация, лимиты частоты, защита от спама, контроль Origin/CSRF, защищённое хранение и доставка. Клиентская валидация не заменяет серверную. Endpoint только same-origin HTTPS.
5. Для аналитики предоставить реальный ID и согласованный механизм согласия. Установить счётчик отдельно; UI согласия устанавливает window.elenaAnalyticsConsent=true только после согласия и false при отзыве. Цели: form_success, phone_click, email_click; будущие реальные ссылки data-analytics=messenger/map включат соответствующие цели. Сейчас соцсети — SVG без URL, карты нет. Личные данные в цели не передаются; запуск счётчика и его cookie требует отдельной настройки.
6. После публикации подтвердить права в Яндекс Вебмастере/Google Search Console, проверить индексирование и региональность; при необходимости подтвердить карточку Яндекс Бизнеса. Доступов нет, эти действия не выполнялись.
