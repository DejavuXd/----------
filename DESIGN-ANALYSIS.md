# Елена Архипова — анализ исходного макета

Дата: 5 ноября 2026 года. Этап: анализ; разработка не начата, согласно требованию дождаться команды «Начинай».

Источник: «Главная 1200px Золотистый вариант.pdf», экспорт Figma. PDF просмотрен целиком и в пяти увеличенных фрагментах. Размер страницы PDF — 1202 × 4252 единицы, основной фон и композиция занимают 1200 единиц по ширине. Контрольный viewport сайта — 1200 CSS px, а не ширина внутреннего контейнера.

Координаты ниже относятся к исходному PDF; округлённые измерения служат ориентиром, а не подтверждёнными свойствами Figma.

Повторяющиеся компоненты: метка секции с оранжевым квадратом, CTA со стрелкой, тонкий разделитель, карточка принципа с линейным знаком, блок факта, поле формы, социальная кнопка. Общие оси: x≈64, 427, 608, 1136. Ширина между основными внешними полями 64 px составляет 1072 px; hero и footer имеют собственную геометрию.

## Основа дизайн-токенов

- `--color-background: #F5EFEB` — цвет большого фонового прямоугольника из PDF.
- `--color-graphite: #2D2D2D` — цвет большого блока практик из PDF.
- `--color-accent: #EA8424` — повторяющийся акцент из векторных объектов PDF.
- `--color-muted: #A39C91` — повторяющийся вторичный цвет из PDF.
- `--color-olive: #66614E` — предварительно по растровому просмотру карточки, уточнить по Figma.
- `--color-card-light: #ECDDD1` — предварительно по растровому просмотру карточки, уточнить по Figma.
- Основное внешнее поле около 64 px, зазор карточек 16 px, внутренние поля карточек и формы около 32 px.
- Скругления крупных карточек около 8 px; тени и градиенты интерфейса не требуются.
- В текстовых объектах PDF присутствуют размеры 8, 10, 11, 12, 14, 20, 28 и 40. Крупные заголовки визуально соответствуют 40, вводный текст и цитата — 28, заголовки карточек — 20. Точное назначение и межстрочные интервалы следует уточнить по Figma.

Цвета растрового просмотра могут отличаться от чисел PDF на единицу RGB из-за рендеринга. Семейство и начертания шрифта не установлены: PDF содержит только имя FigmaGlyphs. Нельзя использовать это имя как реальный веб-шрифт или подбирать замену без согласования. Часть текста при извлечении имеет повреждённую Unicode-карту, поэтому контент необходимо сверять визуально или получить из Figma.

## Изображения

PDF содержит четыре извлекаемых растровых ресурса:

| Ресурс PDF | Назначение | Встроенное разрешение |
| --- | --- | --- |
| X1 | Главный портрет | 1920 × 1080 |
| X2 | Фемида и книги | 1672 × 941 |
| X7 | Наручники | 1728 × 2570 |
| X8 | Портрет в кресле | 1672 × 941 |

Использовать эти изображения возможно без подмены лиц. Однако экспорт PDF не гарантирует исходное качество фотографии: желательно получить оригинальные файлы, особенно для широких экранов. На текущем этапе изображения только проверены на извлекаемость; публичные assets ещё не созданы.

## Критически недостающие данные

1. Названия семейств и начертаний шрифтов, веб-файлы или доступ к Figma с текстовыми свойствами.
2. Оригинальные фотографии и логотип либо согласование использования ресурсов, извлечённых из PDF.
3. Состав остальных направлений практики: тексты, фотографии, количество слайдов; поведение стрелок, цикличность. Автопрокрутка по умолчанию не предполагается.
4. Выбранный серверный способ отправки заявок, получатель и доступный хостинг. Секреты не должны находиться во frontend. Email в footer сам по себе не является обработчиком формы.
5. Утверждённые политика конфиденциальности и согласие, адреса социальных ссылок; подтверждение актуальности контактов и профессиональных сведений из макета. Домен и Open Graph можно определить перед публикацией.

## Последовательность после команды «Начинай»

1. Создать elena-arkhipova на HTML/CSS/Vanilla JS ES Modules и Vite. Сначала tokens.css и базовая семантическая разметка.
2. Извлечь согласованные изображения, подготовить WebP и подключить подтверждённые шрифты.
3. Реализовать Header/Hero и проверить при 1200 px, затем последовательно остальные шесть секций.
4. Добавить навигацию, мобильное меню, подтверждённое переключение практик, доступную валидацию и реальный обработчик формы. Не показывать успешную отправку без подтверждения сервера.
5. Выполнить мобильную интерпретацию и проверить 1920, 1440, 1200, 1024, 768, 480, 375 и 320 px. Увеличение мелких подписей и интерактивных зон на мобильных необходимо для читаемости и доступности.
6. Сравнить браузерные скриншоты с PDF при 1200 px; исправить конкретные различия. Проверить клавиатуру, фокус, reduced motion, отсутствие горизонтального скролла и ошибок консоли.
7. Проверить production-сборку, SEO-основу и доставку тестовой заявки. Домен, canonical и OG настроить после получения данных.
